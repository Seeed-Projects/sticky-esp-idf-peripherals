# reTerminal Sticky 板载外设最小例程

[English](README.md)

面向 Seeed Studio reTerminal Sticky 的 ESP-IDF 板载外设参考工程。同一固件自动识别 SSD1677 / SSD2677。每个外设保留独立的 `demo_xxx.cpp/.h`，方便开发者阅读、复制及基于 AI coding 扩展。

程序按顺序执行外设演示，最后提供按键测试和两种可选的电源测试。演示接口须按下文规则由单个任务顺序调用。

## 环境与构建

- reTerminal Sticky（SSD1677 或 SSD2677）及 USB-C 数据线。
- **ESP-IDF v5.4**；ESP32-S3、32 MB Flash、8 MB 八线 PSRAM。
- 可选：FAT 格式 MicroSD 卡，无需准备任何测试文件。

在 ESP-IDF v5.4 终端进入解压或克隆后的工程目录：

```sh
idf.py set-target esp32s3
idf.py build
idf.py -p PORT flash monitor
```

把 `PORT` 换成串口，例如 Windows 的 `COM8`；`Ctrl+]` 退出监视器。`set-target` 会重置本地配置，仅在首次配置或切换目标时使用。共享配置在 `sdkconfig.defaults`，生成的 `sdkconfig` 留在本机。保留 `dependencies.lock`；首次配置可能需要联网下载 Component Manager 依赖。不需要按屏幕类型分别编译或手工切换驱动。

## 上电执行顺序

| 步骤 | 源文件 | 行为 |
|---|---|---|
| 板级初始化 | `demo_board` | 保持板电源，去选中 SD/显示，创建 SPI2、I2C1/I2C0，安装或复用 GPIO ISR 服务 |
| 温湿度 | `demo_sht40` | 读取 `0x44` SHT40 并检查 CRC，保留有效启动温度供显示使用 |
| 启动画面 | `demo_epaper` | 自动识别控制器，先显示 Testing peripherals，再执行后续外设演示 |
| 蜂鸣器 | `demo_buzzer` | 四段短 PWM 音调 |
| 充电控制 | `demo_charger` | 使能、短暂关闭并恢复低有效充电使能，打印 GPIO40 原始状态 |
| RTC | `demo_rtc` | 探测 `0x51` PCF8563，关闭 CLKOUT，读取有效存储时间；不写示例日期 |
| 电量计 | `demo_battery` | 读取 `0x55` BQ27220 电压、电流、SOC、SOH、容量、温度、循环次数及状态 |
| IMU | `demo_imu` | `0x6A` LSM6DS3TR-C，104 Hz、±2 g / ±250 dps，读取一组加速度/角速度后关闭两者采样 |
| 麦克风 | `demo_microphone` | 16 kHz / 16-bit 单声道 PDM，10 批各最多 512 样本，输出 5 个 RMS 数值 |
| MicroSD | `demo_sdcard` | 挂载、输出容量、尝试读取一个根目录项、卸载；空卡可用，不写入或自动格式化 |
| 显示 | `demo_epaper` | 显示四阶灰条 5 秒，再显示 TOUCH TEST 操作提示和四个圆形参考点 |
| 触摸 | `demo_touch` | 独立任务采集 GT911 15 秒，固定队列积累点并批量绘制 8×8 黑点；详细坐标为 DEBUG |
| 结束 / 空闲 | `demo_epaper` | 显示 Demo complete；仅此画面刷新成功后进入显示待机 |
| 按键 / 电源 | `demo_buttons`、`demo_power` | 开放 10 秒按键测试，再进入电源操作阶段 |

最后汇总成功与不可用/失败的操作数。缺少可选 SD 卡会明确报告；根目录为空也算成功。板电源/SPI 初始化失败时停止流程；I2C 总线或外设不可用时，记录错误并继续其他演示。显示初始化或触摸页面准备失败时，触摸仅采集和输出日志，不绘点。面板句柄可用时仅尝试一次结束页刷新；失败则明确跳过待机，跳过的操作不计为成功。触摸返回成功表示轮询流程完成，不代表已经有手指接触屏幕。

## 目录与复用规则

```text
main/
  main.cpp                 顺序调用与结果汇总
  pin_config.h             引脚及 I2C 地址
  demo_board.cpp/.h        板电源和共享总线初始化
  demo_xxx.cpp/.h          各外设演示
components/
  seeed_epaper/            完整电子纸组件及各控制器后端
  gt911/                   触摸组件
  pcf8563/                 RTC 寄存器与时间合法性检查
  bq27220/                 电量计组件
  button/                  保留原有本地 ISR 补丁的 ESP IoT Button
  debug_logging/           可选驱动诊断
```

所有返回 `esp_err_t` 的入口都需要检查结果。先调用 `demo_board_init()`，再由单个任务按顺序调用演示。总线由板级模块持有整个应用生命周期；这些接口不是可重入/并发框架，没有应用级全局锁。增加任务时，必须串行化同一设备的完整操作，包括挂载/读取/卸载和准备/写入/提交刷新。按键回调和中断中不要执行耗时显示或 SD 操作。

复用时复制对应外设的源文件/头文件、相关 `pin_config.h` 定义和所需组件，保留 `main/CMakeLists.txt` 对应的 `REQUIRES`。复用 `demo_board`，或提供等价的电源和总线初始化。传感器借用 I2C1，仅移除自己临时注册的设备；按键初始化后有意保留句柄和回调。`demo_epaper_init()` 显示进行中提示，`demo_epaper_run()` 执行灰阶和触摸靶点演示，`demo_epaper_finish()` 显示结束提示。显示模块持有 SPI 设备、面板和帧缓冲，返回给调用者的面板句柄仅为借用，调用者不要自行删除。

例如，在板级初始化成功后：

```cpp
const esp_err_t result = demo_sht40_run(demo_board_sensor_bus());
if (result != ESP_OK) {
    ESP_LOGW("example", "SHT40 unavailable: %s", esp_err_to_name(result));
}
```

此片段需要包含 `demo_board.h`、`demo_sht40.h`、`esp_log.h`。单独使用 SD 或显示时，同样要求先创建共享 SPI2、去选中另一个设备；不要在各外设中重复创建或释放总线。

## 双屏显示与触摸

SSD 系列构造入口发送 `0x70`，通过双向 MOSI 读取 ID；`0x07` 选择 SSD2677，其他成功读取值选择 SSD1677。SPI 事务失败直接返回错误，不通过超时猜测另一种控制器。官方组件设置各控制器 BUSY 极性和复位时序。显示 SPI 设备使用 `SPI_DEVICE_HALFDUPLEX | SPI_DEVICE_3WIRE`，SD 保持自己的设备配置。未使用的 SPI 数据引脚全部设置为 `-1`，避免默认值占用传感器 SCL 所在的 GPIO0。

默认日志输出选中的控制器、成功刷新的模式与耗时。需要原始探测 ID 和详细驱动时序时，在 `idf.py menuconfig` 中启用 **Application Debug Logging → Enable e-paper/touch debug logs** 后重新编译。

组件保留黑白全刷、黑白局刷、四阶灰全刷。Gray4 为 **2 bpp**，每字节 4 像素，高位像素在前；触摸使用 **800×480、1 bpp** 缓冲，0 黑、1 白。`demo_epaper_add_dot()` 只修改帧缓冲，`demo_epaper_flush()` 提交有变化的一批点，二者必须由同一个任务调用。已经全黑的点不重复刷新；`demo_epaper_draw_dot()` 保留为 add + flush 的便捷封装。越界坐标拒绝，有效边缘黑点向内调整。

局刷提交完整比较帧，不保证小窗口 SPI 传输。连续 20 次成功局刷后，下一次有变化的更新走黑白全刷；刷新失败后的下一次 flush 也走全刷，成功全刷清零计数。

启动 SHT40 测量成功时设置一次外部波形温度；失败则保留控制器内部温度路径，不是每刷测温。触摸保留本例程原有竖屏逻辑到原生帧缓冲的映射，触摸坐标转换保持不变；状态文字采用 Dashboard 相同的180°逻辑到面板转换，不引入 Canvas 或页面框架。GT911 区分“没有新报告”和“有效松手报告”。触摸独立任务约每 20ms 加 I2C 耗时采集一次，主任务刷新时仍继续采集。队列固定 128 点，满时丢弃新样本并统计；相同触点 ID 的重复坐标过滤。主任务每批最多合并 128 点后刷新一次，不再额外等待 200ms。改善的是采集，不改变屏幕波形耗时；画面仍按批延迟更新，不是连续画线应用。新增触点 ID 首次按下时输出一行 INFO 原始/屏幕坐标，按住和移动不重复此行，松开后再按才输出。移动详细坐标保留默认关闭的 `ESP_LOGD`，采集不依赖日志；需要查看时将编译最大日志等级设为 DEBUG，并对 `demo_touch` 启用 DEBUG。

采集任务每秒输出剩余时间，不受显示刷新阻塞；触摸阶段的成功刷新耗时降为 DEBUG，启动显示结果和刷新错误仍可见。采集持续 15 秒，结束先等待任务停止确认，再释放触摸控制器及队列，并最多提交一批剩余点。正在执行的刷新可能延长整体流程；停止确认超时则保留资源、返回错误，重启前不能再次启动触摸。

结束页刷新成功后才进入显示待机。显示待机仍保持 EPD_EN 为高，ESP32 继续运行。

## 按键与电源测试

10 秒按键测试期间只输出事件。出现电源提示页后，先松开所有键再重新按下。长按 UP 约 1 秒请求 ESP32 深度睡眠，长按 AI 约 1 秒请求板级关机。满 1 秒立即开始收尾，最终切换等所有键稳定松开 60 ms。DOWN 不触发电源操作。

- 深睡保留主板电源锁存，配置 UP、DOWN、AI 三键唤醒；唤醒后从头运行例程。
- 关机沿用官方 HOLD/LOCK 时序。电池供电时，断电后按 AI 重新开机。外部供电使主板仍运行时，例程沿用官方策略，确认按键松开后软件重启一次。
- 确认活动外设结束且 SD 已卸载后，刷新提示页、让屏幕控制器休眠，再关闭屏幕、触摸、麦克风及 SD 电源使能。准备后若转换失败，请复位后重试。
- 外部 RTC 在备份供电有效时继续走时。关机电流应在实机测量，本例程不承诺固定值。

随附 GT911 驱动保留官方固件实现。本例程演示单指触摸诊断。队列丢弃数仅统计应用队列溢出，不代表控制器报告全过程没有遗漏。

## 引脚与接口

| 功能 | GPIO / 地址 |
|---|---|
| POWER / OK / AI、UP、DOWN | 4、5、6，低有效 |
| Power hold / lock、蜂鸣器 | 45 / 46、48 |
| 充电使能 / 原始状态 | 39（低有效）/ 40 |
| 电量计 / IMU 中断 | 7（共享板信号，本例不使用）|
| I2C1 SCL / SDA | 0 / 1；RTC `0x51`、BQ27220 `0x55`、SHT40 `0x44`、IMU `0x6A` |
| I2C0 SCL / SDA | 2 / 3；GT911 |
| 触摸 EN / INT / RST | 42 / 21 / 41 |
| PDM CLK / DATA / EN | 19 / 20 / 38 |
| 共享 SPI2 CLK / MOSI / MISO | 13 / 14 / 12 |
| 电子纸 CS / DC / RST / BUSY / EN | 15 / 16 / 17 / 18 / 47 |
| SD CS / EN / DETECT | 8 / 10（高有效）/ 11（插卡低）|

`demo_board_init()` 只创建一次 SPI2；SD 与显示各用自己的片选，外设模块均不释放总线。

## 数据与失败边界

- **RTC：** 拒绝 VL、非法 BCD 和不存在的日期，失败不修改输出；不联网校时、不转换时区、不自动写日期。正确时间需另行设置。
- **电量/充电：** 750 mAh 原装板的 R46=100mΩ，官方电量计设计参数为7500，与电流/容量10倍标度相符。演示先检查 DesignCapacity()==7500，再以每寄存器单位0.1物理单位解释电流/容量；明确标注原装配置假设并保留原始值。检查失败或参数不匹配时仅显示原始单位。此检查不等于增益/偏移标定，自定义配置须单独核对；电压、温度和百分比不除以10。电量计温度不等于已认证的电芯温度。GPIO40 是原始状态，不是实测充电电流，也不是完整的 Full/Charging/Discharging 分类。充电演示最后恢复 GPIO39 为低。
- **麦克风：** 每批去除直流分量后计算 RMS，为相对采样幅值，不是标定后的声压 dB SPL；它是短诊断，不是 1 秒录音，也不生成音频文件。
- **SD：** 挂载现有 FAT、输出容量、打开根目录、只调用一次 `readdir()` 后关闭并卸载。不统计文件数、不递归、不列文件名、不要求测试文件，也不宣称验证所有文件内容；空根目录成功。底层 FAT 访问耗时仍取决于介质。应用不写入或自动格式化，但挂载未强制只读。卸载失败后禁止重试，须重启；不复用旧卡指针。访问中不要拔卡。
- **IMU：** 静止时加速度向量合量约 1 g，各轴分量取决于方向；陀螺仪应接近零，可能存在偏移。读取前启用 BDU 和寄存器自增。
- **错误：** 返回结果包含尽力清理失败，不代表所有硬件异常都能无重启恢复。保留 WARN/ERROR 日志。

## 板上核查

对**两种屏幕分别**核查控制器识别、四种可区分灰阶、开始/触摸/结束提示、四角/中心触摸点，以及多次绘点跨越维护全刷。检查无卡、空的已格式化卡、根目录很多条目的卡，确认 SD 之后显示正常；触摸对照逐点 DEBUG 开/关，快速点击/移动、原地按住及队列饱和，并核查传感器、按键及充电使能恢复。汇总日志不是硬件认证；拔卡或清理失败后先重启再尝试。本例不提供睡眠电流或寿命认证数据。
